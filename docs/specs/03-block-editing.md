# 子 PRD · M3 块级往返编辑（核心交互）

> 所属整体 PRD：`docs/PRD.md` 第 5 节
> 对应任务：T5
> 状态：设计中

## 1. 背景与目标

WeMark 以「聊天」形式编辑 Markdown，块级往返编辑是其灵魂：用户点击渲染区的任意内容块，其 Markdown 源码回到编辑区，修改后发送即**原位更新**。本模块负责这条链路的全部状态与交互，目标是「直观、方便」——单击即编辑、改完即回归、位置不跳动。

## 2. 需求详述

### 2.1 数据模型

```ts
// 内容块
interface Block {
  id: string;            // 唯一标识（如 nanoid/uuid）
  source: string;        // 该块的 Markdown 源码（原文）
  type: BlockType;       // heading | paragraph | list | code | image | table | blockquote | mermaid | ...
  index: number;         // 在文档中的位置（0 起）
}

// 编辑区状态
type EditorState =
  | { mode: 'idle' }
  | { mode: 'editing'; blockId: string };

// 未发送草稿（仅存内存）
interface Draft {
  id: string;
  source: string;                                          // 未发送的源码
  target: { type: 'new' } | { type: 'block'; blockId: string }; // 原本要写到哪里
  preview: string;                                          // 列表里的内容预览
  createdAt: number;
}
```

### 2.2 三种状态机

| 状态 | 进入条件 | 发送行为 | 退出条件 |
|------|---------|---------|---------|
| `idle` | 初始 / 取消 / 发送完成 | 新块追加到**文档末尾** | 点击某块 → editing |
| `editing(blockId)` | 点击某内容块 | 该块**原位替换** | 发送完成 / 取消 / Esc |

### 2.3 功能点

- **F1 点击回填**：点击渲染区某块 → 该块进入「正在编辑」态 → 其 `source` 回填编辑区 → 编辑区切到 `editing(blockId)`。
- **F2 原位更新**：编辑中发送 → 用新源码重新解析该块 → 在**原位置**替换渲染 → 清空编辑区回到 idle。
- **F3 取消编辑**：取消按钮 / Esc → 清空编辑区回到 idle，块退出高亮，内容不变。
- **F4 新建块**：idle 下发送 → 新块追加到末尾。
- **F5 编辑目标提示**：editing 状态下编辑区上方显示「正在编辑：第 N 块」提示条 + 取消按钮。
- **F6 视觉反馈**：正在编辑的块有高亮/描边，滚动到可视区，区别于其它块。
- **F7 自动入草稿**：编辑区有未发送内容时，发生「离开」动作（点击别的块 / 切换文档 / 关闭应用），自动存为一条草稿，不丢内容。
- **F8 草稿箱下拉**：编辑区底部工具栏提供「草稿箱」入口，下拉列出未发送草稿，点击恢复。
- **F9 草稿恢复**：恢复草稿时连同其 `target` 一起恢复（新内容→idle；某块→editing(blockId)），并回填 `source`。

## 3. 交互与状态细节

### 3.1 点击块的行为

- **单击**块体即进入编辑（不设「选中后再点编辑」的两段式）。
- 点击块内链接、图片等可交互元素时，**不**触发编辑（避免误触），仅点击空白/文本区域触发。

### 3.2 键盘交互

| 按键 | 行为 |
|------|------|
| Enter | 发送（idle：追加；editing：原位更新） |
| Shift+Enter | 输入框内换行 |
| Esc | 取消编辑 / 清空并回到 idle |
| Cmd/Ctrl+Enter | 强制发送（编辑器获得焦点时也生效） |

### 3.3 状态流转图

```
        点击块 B
 idle ──────────────► editing(B)
  ▲                    │
  │ 取消/Esc           │ 发送（原位替换 B）
  │                    ▼
  └──(发送:追加到末尾)─ idle
```

### 3.4 边界情况

- 编辑 A 块时点击 B 块：A 的未提交内容**自动入草稿**，随后切换到 B（回填并进入 editing(B)）。
- 编辑中删除该块：若块因外部操作消失，editing 状态回退为 idle。
- 空内容发送：忽略（不生成空块）。
- 源码未变化就发送：不触发重渲染，仅退出 editing。

### 3.5 草稿箱交互

- **入口**：编辑区底部工具栏「草稿箱」按钮（历史/时钟图标），可带未发送数量角标；无草稿时置灰。
- **列表项**：目标标签（「新内容」/「第 N 块」）+ 内容预览（截断）+ 时间；hover 显示删除按钮。
- **恢复**：点击草稿 → 编辑区回填 `source` 并切到对应状态（新内容→idle；某块→editing(blockId)），目标块高亮。
- **清理**：发送成功后清除对应 `target` 的草稿；支持手动删除；最多保留 10 条，超出淘汰最旧。
- **持久化**：MVP 仅存内存，关闭应用即清空。
- **当前内容不入列表**：编辑区正在写的内容即「最顶上那份」，不在下拉里重复出现。

## 4. 验收标准

- [ ] 点击块后，编辑区出现该块的 Markdown 源码，且块高亮。
- [ ] 编辑区显示「正在编辑：第 N 块」。
- [ ] 修改后发送，块在**原位置**更新，不追加、不重排。
- [ ] 取消/Esc 后编辑区清空，块内容不变。
- [ ] idle 发送，新块追加到文档末尾。
- [ ] Enter 发送、Shift+Enter 换行、Esc 取消均按预期工作。
- [ ] 空内容发送被忽略，无空块产生。
- [ ] 编辑 A 块时点击 B 块，A 的未提交内容自动进入草稿箱，不丢失。
- [ ] 草稿箱下拉能列出未发送草稿（含目标标签与预览），点击后回填源码并恢复到对应编辑状态。
- [ ] 发送成功后对应草稿被清除；草稿可手动删除；超过 10 条自动淘汰最旧。
